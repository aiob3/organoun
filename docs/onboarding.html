Máquina · uma vez

O clone do Organoun instala CLI, runtime e skill.

Projeto · quando necessário

Cada repositório recebe seu próprio deployment local e ignorado pelo Git.

1

Instale o Organoun uma vez

Abra um terminal no diretório em que você escolheu guardar o checkout. O clone cria a pasta organoun no diretório atual; o Organoun não impõe uma localização.

gh repo clone aiob3/organoun
cd organoun
./scripts/install-organoun.sh --apply
export PATH="$HOME/.local/bin:$PATH"
command -v organ

Resultado esperado: /home/SEU_USUARIO/.local/bin/organ.

O export vale para a sessão atual e para o tmux iniciado a partir dela. Depois, inclua ~/.local/bin no PATH permanente do seu shell.

Não execute organ onboard aqui. O checkout de instalação só guarda o código-fonte. Servidor, CWD remoto e raiz de projeto pertencem ao projeto-alvo.
2

Entre no projeto-alvo

Escolha o repositório em que a ponte deve atuar. O exemplo abaixo usa uma Calculadora.

cd /caminho/absoluto/para/calculadora
git rev-parse --show-toplevel

O segundo comando deve imprimir exatamente a raiz do projeto.

3

Inicie o tmux antes do Codex

Se ainda não estiver dentro de uma sessão tmux, crie a sessão que será o owner visível.

tmux new -s calculadora
codex

Se já estiver no tmux, permaneça na raiz do projeto e execute apenas codex. Nenhuma sessão paralela deve ser criada fora da visão do operador.

4

Faça a chamada no Codex

Envie exatamente:

Codex, inicialize o $organoun neste repositório.
CondiçãoResultado obrigatório
organ ou skill ausentesInformar a ausência e parar.
Codex fora do tmux visívelOrientar saída e retomada dentro do tmux; parar.
Deployment ausenteExecutar somente organ onboard; apresentar o recibo e parar.
Deployment válidoExecutar organ init --json.
5

Primeiro uso: onboard

O operador informa diretamente no terminal:

  1. Local project root: o resultado de pwd -P na raiz;
  2. Remote SSH alias: o alias autorizado no ~/.ssh/config local;
  3. Remote CWD: o caminho absoluto de trabalho no endpoint.

O onboarding usa ssh -G apenas para resolver a rota local. Não conecta, não abre pane e não inicia Claude.

state=connected
Organoun Connected

O projeto recebe .organoun/deployment.json e .organoun/state/, ambos ignorados pelo Git. O Codex apresenta o recibo e para; não executa init na mesma interação.

6

Ative o projeto

Na interação seguinte, ainda no projeto e no tmux visível, repita a chamada.

Codex, inicialize o $organoun neste repositório.

Com o deployment válido, o Codex executa organ init --json.

state=initialized

Organoun ativo nesta sessão. O que vamos criar hoje?

O controle retorna ao operador. Nenhum pane subordinado é aberto antes de uma nova intenção e autorização visível.

Se o Codex foi iniciado fora do tmux

  1. saia do Codex;
  2. execute tmux new -s NOME ou entre numa sessão existente;
  3. volte à raiz do projeto;
  4. execute codex resume ou uma nova sessão com codex;
  5. repita a chamada de inicialização.
✓

Comprovação concluída

  • command -v organ encontrou a instalação local.
  • O Codex foi iniciado no tmux visível.
  • O primeiro uso retornou state=connected.
  • A retomada retornou state=initialized.
  • O Codex informou “Organoun ativo nesta sessão. O que vamos criar hoje?”.
  • Nenhum pane foi criado antes de nova autorização do operador.
